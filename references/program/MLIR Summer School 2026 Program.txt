Building Transformations
Building Transformations
Lead: Matthias


Session 5: Pass Infrastructure + C++ API for modifying IR
Duration: 90 min
Theme: How do I run code over the IR, and how do I change the IR by hand?
Learning objectives: By the end, students can: write and register a pass from TableGen, run it standalone/nested via mlir-opt, navigate the SSA + region IR model in C++, and mutate IR directly with builders and Operation/Value/Block APIs.
Part A — Pass Infrastructure (≈50 min)
1. Motivation & the conceptual model (8 min)
What a pass is: a transformation scoped to one operation instance ("the current op").
A pass manager is a pipeline anchored at an op type; nesting mirrors the op hierarchy.
Big mental model slide: PassManager → OpPassManager → Pass, with OpToOpPassAdaptor driving nesting.


2. Anatomy of a pass (12 min)
Pass, OperationPass<OpT>, OperationPass<>, InterfacePass<I>, PassWrapper (mlir/include/mlir/Pass/Pass.h).
The three things you implement: runOnOperation(), getOperation(), signalPassFailure().
Live walkthrough of a real pass: mlir/lib/Transforms/CSE.cpp (small, readable, uses analyses + statistics).


3. Declaring passes with TableGen (12 min)
def Pass<"arg", "anchor-op"> in PassBase.td; the anchor op argument and what "" (generic) means.
The generated Passes.h.inc 3-include pattern: GEN_PASS_DECL, GEN_PASS_DEF_*, GEN_PASS_REGISTRATION.
Real example: mlir/include/mlir/Dialect/Arith/Transforms/Passes.td + EmulateWideInt.cpp (struct Pass : impl::Base<Pass>, using Base::Base).
options (Option<>, ListOption<>), statistics (Statistic<>), dependentDialects.


4. Pass managers, nesting & pipelines (10 min)
addPass, nest<func::FuncOp>(), addNestedPass<>; implicit vs explicit nesting.
Textual pipeline syntax students must memorize: builtin.module(cse, func.func(canonicalize,cse)), options as pass{opt=val}.
Registration paths: PassRegistration<>, PassPipelineRegistration<>, dialect bundles (registerArithPasses()), and registerAllPasses().


5. Analyses, threading & debugging (8 min)
getAnalysis<T>(), getCachedAnalysis<T>(), and the preservation contract: markAllAnalysesPreserved() / markAnalysesPreserved<DominanceInfo>() (show in CSE).
Threading model: sibling isolated-from-above ops run in parallel ⇒ the "only touch the current op and its descendants" rule, and why it exists.
Debugging toolbox: --mlir-print-ir-after-all, --mlir-pass-statistics, --mlir-pass-timing, crash reproducer.
Part B — C++ API for Modifying IR (≈35 min)
6. The IR data model in C++ (8 min)
Operation → Region → Block → Operation; Value = OpResult | BlockArgument; uses tracked via OpOperand.
Use-def chains: getUsers(), getUses(), use_empty(), getDefiningOp() (null for block args).


7. Builders & creating IR (12 min)
Builder (context-global: types/attrs, e.g. getI32Type(), getIntegerAttr()) vs OpBuilder (insertion-point aware).
Insertion points + OpBuilder::InsertionGuard (RAII), setInsertionPointToStart/After, atBlockBegin/End.
Canonical op creation: OpTy::create(builder, loc, ...) — note the old builder.create<OpTy>(...) is now deprecated. ImplicitLocOpBuilder for implicit locations.
Creating blocks/regions: createBlock, block arguments, Block::splitBlock.


8. Direct mutation (12 min)
Operation: setOperand, eraseOperand, moveBefore/After, setAttr, erase() (requires no uses).
Value::replaceAllUsesWith, Operation::replaceAllUsesWith, replaceUsesOfWith.
Safe iteration while mutating: llvm::make_early_inc_range(value.getUses()).
Walking IR: op->walk(...), WalkResult (advance/skip/interrupt), post-order erase safety.


9. Bridge to Session 6 (3 min)
Direct mutation is fine in passes/frontends, but it bypasses listeners. Inside pattern-based transforms you must use a rewriter — segue to Session 6.
Hands-on / demo ideas: write a func.func pass that inserts a constant + an arith.addi, then rewrites all uses of an argument; run it standalone and nested; observe analysis invalidation via statistics.
Session 6: Rewriter, Pattern Driver Infrastructure
Duration: 90 min
Theme: The idiomatic way to transform IR — declarative patterns applied by a driver.
Learning objectives: Students can: write OpRewritePatterns with correct rewriter discipline, assemble and freeze a RewritePatternSet, drive them with both the greedy and walk drivers, understand how folding integrates, and know where dialect conversion fits (and why it's a separate framework).


0. Recap & framing (5 min)
Why patterns over hand-written walks: local, composable, benefit-ordered, applied automatically.
The pipeline slide: RewritePatternSet → FrozenRewritePatternSet → PatternApplicator → Driver → PatternRewriter.


1. The rewriter hierarchy (12 min)
OpBuilder → RewriterBase → {IRRewriter, PatternRewriter} (all in PatternMatch.h).
Why you MUST use the rewriter inside patterns: drivers act as a RewriterBase::Listener; direct mutation breaks worklist bookkeeping (debug builds fatal-error on it).
Key RewriterBase API: replaceOp, replaceOpWithNewOp<OpTy>, eraseOp, modifyOpInPlace (start/finalize/cancelOpModification), inlineRegionBefore, mergeBlocks, notifyMatchFailure.
IRRewriter for standalone (non-pattern) transforms that still need notifications.


2. Writing patterns (15 min)
Pattern → RewritePattern → OpRewritePattern<OpTy>; also OpInterfaceRewritePattern, OpTraitRewritePattern.
Just one method: matchAndRewrite(OpTy, PatternRewriter&) (no split match/rewrite in C++ base).
PatternBenefit (0–65535) and how ordering/ties work.
Live read of a real, tiny pattern: SelectToExtUI in mlir/lib/Dialect/Arith/IR/ArithOps.cpp (matchPattern, m_One(), replaceOpWithNewOp).
hasBoundedRewriteRecursion, getGeneratedOps (debugging recursion/cost).


3. Assembling & freezing patterns (8 min)
RewritePatternSet::add<...>(ctx); the populateXxxPatterns(RewritePatternSet&) convention.
FrozenRewritePatternSet: indexing by op name, expanding interface/trait patterns, shareable across threads, enable/disable labels.


4. The greedy driver + folding (20 min)
Entry points: applyPatternsGreedily(Region&/Operation*), applyOpPatternsGreedily(ArrayRef<Operation*>).
GreedyRewriteConfig knobs: useTopDownTraversal, maxIterations (default 10), maxNumRewrites, scope, strictness, enableFolding (default on), enableConstantCSE, regionSimplificationLevel, listener.
Worklist semantics: LIFO + O(1) removal; per op → dead-check → fold → pattern match; listener re-enqueues inserted/modified ops and operand producers on erase.
Folding inside the loop: Operation::fold() / hasFolder, OpFoldResult, materializeConstant; folding runs before patterns, plus constant CSE on worklist population.
Convergence and what "didn't converge" diagnostics mean.


5. The walk pattern driver (10 min)
walkAndApplyPatterns (mlir/lib/Transforms/Utils/WalkPatternRewriteDriver.cpp) — a simpler alternative driver.
Single deterministic walk, no worklist, no fixpoint iteration, no folding: each op is visited once.
When to prefer it: you know one pass is enough (e.g. straightforward lowering/expansion), you want predictable cost and ordering, and you don't need re-visitation. Still uses PatternRewriter discipline + listener for safe erase/insert during the walk.
Contrast slide: greedy (fixpoint, folding, more expensive, can loop) vs walk (one shot, cheap, no convergence guarantees).


6. Declarative & advanced patterns (10 min)
DRR (Pat<...> in TableGen) → compiled to C++ matchAndRewrite — show a Toy ToyCombine.td snippet.
PDL/PDLL as the declarative pattern-as-data path (match/rewrite split at bytecode level) — mention, don't deep-dive.
Transform dialect: transform.apply_patterns wraps the greedy driver.


7. Dialect conversion — brief positioning (7 min)
A separate framework for type/dialect legalization, not a same-type simplifier.
Vocabulary only: ConversionPattern/OpConversionPattern (note the adapted operands), ConversionPatternRewriter, TypeConverter, ConversionTarget (legal/illegal/dynamic), applyPartialConversion/applyFullConversion.
Contrast table (greedy/walk vs conversion) and the key warning: don't drop conversion patterns into a greedy pass — they need the conversion driver and rewriter. Full treatment is its own session.
